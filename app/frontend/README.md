# Frontend — «На городской карте»

React + TypeScript + Vite + TanStack Query + Zustand + OpenLayers.

## Архитектура

```
src/
  pages/                 # маршруты и композиция экранов
  widgets/               # AppLayout, MapWidget и крупные UI-блоки
  features/              # пользовательские действия
  entities/              # доменные данные и query hooks
  shared/
    api/                 # API client
    theme/               # ThemeProvider и режимы темы
    styles/              # design tokens и semantic theme tokens
```

## Design System

Визуальное направление: минимализм + glassmorphism для боковой навигации.

- Light / Dark / System — переключение темы доступно из верхней панели.
- Выбор темы сохраняется в localStorage; системный режим реагирует на prefers-color-scheme.
- Постоянная боковая панель на Desktop: развёрнутая и компактная версии.
- На мобильных — выдвижная навигация.
- Стеклянный эффект ограничен боковой панелью; контентные карточки остаются минималистичными.
- Цвета, поверхности, типографика, отступы, радиусы и тени централизованы в shared/styles/tokens.css и themes.css.
- Компоненты используют семантические CSS-переменные, чтобы будущая смена визуального стиля не требовала переписывать бизнес-логику.
- На карте используется адаптация OSM-плиток для тёмной темы; после выбора картографического провайдера её нужно проверить и при необходимости заменить на нативный тёмный стиль.

## Реализованный интерфейс

- Главная карта с категориями, bbox-загрузкой и компактной карточкой выбранной точки.
- Публичная форма отправки PointRequest с полями API-контракта и отображением ошибок.
- Адаптивная оболочка приложения и мобильная навигация.
- Визуальный каркас кабинета модератора по адресу /moderator.

## Что пока не подключено

- Поиск по названию/адресу — backend-контракт пока отсутствует.
- Выбор координат нажатием на карту в форме — пока координаты задаются вручную.
- Защищённая очередь заявок, авторизация по X-Moderator-Key и действия approve/reject — следующий этап.
- CDN и окончательный картографический провайдер/API-ключи — отдельные задачи инфраструктурного backlog.

## Технологии и кеширование

- Vite + React + TypeScript
- BrowserRouter
- TanStack Query
- API client с единым ApiError
- OpenLayers
- bbox-загрузка точек
- кеш категорий 5 мин / 30 мин GC
- кеш точек 30 сек / 5 мин GC
- Vite proxy /api -> FastAPI
- публичная конфигурация отделена от секретов

Стратегия кеширования: Browser HTTP Cache + TanStack Query + CDN/Edge Cache. Публичные GET допускают короткий CDN TTL; mutation и moderator API публично не кешируются. Hashed Vite assets в production должны отдаваться с immutable cache.
